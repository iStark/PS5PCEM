Follow-up: the reporter confirmed that linking succeeds and supplied a loading

[Issue #8](https://github.com/iStark/PS5PCEM/issues/8) reports 21 unresolved
`libkernel` imports from `fakelib/libSceAmpr.sprx` in ASTRO BOT PPSA21567.
All 21 now have named, NID-checked implementations. The loader still rejects
unknown strong imports; it does not skip the guest module or silently bind
unknown functions to a successful return.

This is a linker and kernel-interface fix, **not a verified PPSA21567 gameplay
result**. The reporter's converted module and title build are not available
locally. Existing local ASTRO BOT coverage uses PPSA21564 and cannot establish
compatibility of a different `fakelib` implementation.

## Implemented behavior

- The kernel AMM writers emit native packed map, direct-map, unmap, remap,
  multimap and masked protection commands, including memory-type and GPU-mask
  variants. A null destination measures the command without modifying memory.
  Invalid arguments and inaccessible output pointers return errors.
- Indirect-buffer submission snapshots and validates the command stream,
  executes mappings in order, writes result/error-offset records, and allocates
  completion IDs that can be waited on. The implementation completes
  synchronously. Submissions without an output ID consume no completion slots.
- Multimap aliases retain shared physical backing. A write through either
  address is visible through the other. Remapping preserves the contents and
  removes the old virtual mapping after the new mapping succeeds.
- Masked protection changes preserve unselected permission bits and apply
  separately across existing mapping intervals. Memory types and GPU-mask IDs
  are retained in mapping metadata and virtual-query results.
- Mapper allocation uses the existing direct-memory pool, including AMPR's
  donated automatic allocation ranges. Mapper parameters expose the same
  virtual windows as PS5PCEM's existing `libSceAmpr` implementation. Failed
  mappings return their allocation; completion pointers are checked again
  after commands that may have unmapped or protected those pointers.
- `sceKernelMtypeprotect` updates real page permissions and memory-type metadata.
  `sceKernelReleaseFlexibleMemory` unmaps flexible pages, restoring their budget.
  `sceKernelAioSetParam` validates and writes the five scheduling fields; the
  existing synchronous AIO executor does not require a separate tuned scheduler.

## Remaining limits

This does not implement the complete hardware AMM/AMPR protocol. Sparse PRT
execution and non-mapper command opcodes are rejected. Overlapping remaps,
aliases of non-direct memory, and replacement of occupied alias destinations
are rejected before modifying the source. There is no asynchronous mapper
priority scheduler or hardware GPU-mask routing. The final two mapper parameter
words are reserved as zero. Completion/error behavior and the converted
PPSA21567 module still need verification with the reporter's files.
