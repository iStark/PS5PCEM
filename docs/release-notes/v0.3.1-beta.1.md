# PS5PCEM 0.3.1-beta.1

243 commits since `v0.3.0-alpha.4`. The headline is Ghost of Yōtei: it now loads
a 3D world and composes its in-game interface over it, where the previous release
stopped at the brightness slider. A new title, Dreaming Sarah, plays through at
60 FPS. And a crash that made this emulator do nothing at all on a large class of
processors is fixed — if an earlier release started and vanished on your machine,
read the first section.

## Fixed: nothing happened at all on CPUs without AVX-512

A release binary is built on one machine and run on many. `build.zig` asked Zig
for the target without naming a CPU, so Zig used the **build machine's own** — and
a release produced on a host with AVX-512 executed an AVX-512 instruction on a
Ryzen 5000, or any other CPU without it. The process died with
`STATUS_ILLEGAL_INSTRUCTION` (`0xc000001d`) before it opened a window, touched
Vulkan, or reached any code that could report why. From the outside that is
indistinguishable from the program not starting: no error, no log, nothing.
Unblocking the file, running as administrator and allowing it through SmartScreen
all changed nothing, because none of them was the cause.

Builds are now pinned to the **x86-64-v3** baseline — AVX2, BMI2 and FMA, which
every CPU able to drive this emulator has had since 2013. `-Dcpu=` and `-Dtarget=`
still override it for anyone building their own.

This was reported by community members who did the diagnosis themselves, down to
the Event Viewer exception code and the `build.zig` line responsible. That report
is the reason it is fixed.

## Ghost of Yōtei: into the game

![Ghost of Yotei difficulty selection composed over a loaded 3D scene](https://raw.githubusercontent.com/iStark/PS5PCEM/v0.3.1-beta.1/docs/images/yotei-difficulty.png)

The title now reaches and renders its **difficulty selection** over a fully loaded
3D scene — geometry, bark and rock materials, ember particles, depth and lighting
— with the option, its description, the arrows, the position dots and the cross
glyph all legible. Earlier releases stopped at brightness calibration.

This is **not playable**, and the release does not claim it is. Frames there
measure **1504–1554 ms** for 321 draws and about 1330 compute dispatches, which is
0.6 FPS. Reaching that screen takes minutes of intro and scene loading, and how
many minutes varies widely between runs of the same build.

What moved it there, mostly: exact scalar provenance through masked loops and lane
spills, BVH ray-intersection decoding and bounded GFX10 ray lowering, guest
tessellation factor and domain interfaces, custom per-vertex fragment
interpolation, fragment position and front-facing inputs initialized from the
rasterizer, packed SNORM animation buffers, and a long list of RDNA2 lowering
corrections — display clamp, output scaling, GDS modifiers, round-toward-zero in
packed half conversion, and SCC after scalar Boolean and 64-bit logical operations.

## Dreaming Sarah: playable and completable

![Dreaming Sarah world scene with an NPC](https://raw.githubusercontent.com/iStark/PS5PCEM/v0.3.1-beta.1/docs/images/dreaming-sarah-gameplay.png)

Confirmed by the maintainer on September 15, 2026. Menus, the animated title,
world scenes, characters and NPCs render correctly, and the title menu and first
scene hold the **60 FPS** cap on an RTX 3070 Ti — 5,280 flips over 90 seconds. The
frame rate falls on the second gameplay scene; that scene is not yet measured.

Two things had to be fixed to load it. The loader now reads an **absent dynlibdata
tail as absent**: a module can carry the `PT_SCE_DYNLIBDATA` header with nothing
behind it — this title's `libc.prx` places the segment at its own last byte and
claims 26 more, in the untouched file as much as in a patched one — so there is
provably nothing there to read. Only a bare ELF can say that; a SELF still reports
truncation, and so does any segment that starts inside the image and runs off the
end. Three **libSceAgc** imports are now bound, with `sceAgcJumpPatchSetTarget`
implemented rather than stubbed, because reporting a jump patch that did not
happen leaves a command stream that still reads as valid and jumps wherever the
packet already pointed.

`TruncatedSelf` also used to name neither the file nor the shortfall, while the
failure could be in any module. It now prints the range it wanted against the
length it had.

## Launcher

- **Vulkan is now checked, not asserted.** At startup the launcher loads the
  Vulkan loader, creates an instance at the **1.2 the renderer itself requires**,
  and enumerates devices. It reports one of four outcomes: ready, with the API
  version and adapter name that someone filing a bug report needs; no loader; no
  device; or a driver below 1.2 — each phrased as what to do about it, in all
  eight interface languages.
- **Speed / Graphics rendering preset**, mirroring the console's two modes and
  defaulting to Speed. Speed enables sampled-image backing reuse and deferred
  retirement; Graphics keeps the conservative synchronous paths.
- **Output resolution preference**, defaulting to 1080p.
- A link to **ps5pcem.com** in the sidebar.

## Performance

`sceKernelBatchMap` was stopping the guest for 200–1200 ms per batch. Reservation
and metadata intervals are now edited in place, unmapped intervals removed in
place, and adjacent batch-map entries issued as one host mapping. Per-frame guest
time outside the submit path fell from roughly 1000 ms to 6–11 ms.

Around 77 further performance changes: graphics pipelines, resident buffers and
render targets indexed by address; detiled textures uploaded without a CPU round
trip; sampled image views shared and backings reused; identical fixed direct
mappings reused; wave ballots, EXEC predicates, dispatcher registers and buffer
address calculations reused within SPIR-V blocks; alternating LS/HS analyses
retained; larger graphics translation working sets.

A guest mip pyramid is now **sampled from the images that produced it**, rather
than read back from guest memory the levels were never published to — which was
handing shaders a blank texture. Two real defects surfaced while writing it: a
copy sized from the producer instead of the destination level (a guest rounds a
level up where Vulkan rounds down, so level 7 of a 960×540 chain arrives 8×5
against a 7×4 level), and an evicted chain leaving live views onto freed memory.
Both ended in device loss before they were understood.

## Compatibility: a regression found and fixed

Mapping a whole granularity-aligned range as one host view is fewer calls, and it
is what took Yōtei's batch maps under 50 ms. It also **stopped Cat Quest III**: 60
frames against 2640 in the same 100 seconds, three runs of each, with the title
falling into the stall watchdog. That change is reverted. The coalescing around it
stays and carries most of the original win; Yōtei's batch maps cost 139–209 ms
again, which is the price of a title that runs at all.

Why the wider view hurts that particular guest is still unknown, and the
diagnostic the change was originally justified with reports zero on the broken
build too — so it never spoke to the question.

## Known limits

- Ghost of Yōtei is **not playable**: 0.6 FPS in scenes, minutes to reach them.
- Tetris Effect: Connected, REANIMAL, The Precinct and Rita's Rewind reach the
  milestones described in
  [project-status.md](https://github.com/iStark/PS5PCEM/blob/v0.3.1-beta.1/docs/project-status.md);
  gameplay is not claimed for any of them.
- 10 SPIR-V tests fail, as they did before this release; 1194 of 1205 pass.
- Vulkan validation layers cannot be enabled on a host whose SDK registered its
  layers under a path that no longer exists. The launcher's new check reports the
  driver, not the SDK.

## Requirements

Windows x64, a Vulkan 1.2 driver, and a CPU with AVX2 — 2013 or newer. Game
content is not included and is not distributed with this project.
